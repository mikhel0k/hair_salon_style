# Запуск API и тестов

Инструкция для локальной работы с backend-сервисом парикмахерской.

## Что понадобится

- Python 3.10 или новее;
- Docker и Docker Compose;
- файл `.env` с настройками PostgreSQL и Redis.

Команды ниже выполняются из каталога проекта:

```bash
cd /Users/lev/PIS/hair_salon_style
```

Если проект скопирован на другой компьютер, укажите его фактический путь вместо этого.

## 1. Подготовить настройки

В корне проекта должен лежать файл `.env`. В нём нужны переменные:

```dotenv
POSTGRES_DB=
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_HOST=localhost
POSTGRES_PORT=5432

POSTGRES_DB_TEST=
POSTGRES_USER_TEST=
POSTGRES_PASSWORD_TEST=
POSTGRES_HOST_TEST=localhost
POSTGRES_PORT_TEST=5433

REDIS_HOST=localhost
REDIS_PORT=6379

LOG_LEVEL=INFO
LOGIN_FOR_GMAIL=
PASSWORD_FOR_GMAIL=
SEND_LOGIN_CODE_EMAIL=false
```

Заполните имена баз, пользователей и пароли для основной и тестовой PostgreSQL. Значения должны совпадать с настройками, которые Docker Compose читает для контейнеров. Переменные Gmail нужны настройкам приложения; при локальном запуске тестов отправка писем выключена.

Не добавляйте `.env` в Git: в нём хранятся пароли и другие настройки. В этом репозитории файл `.env` исключён из Git.

## 2. Установить зависимости Python

Создайте виртуальное окружение и установите пакеты:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

При следующих запусках достаточно перейти в каталог проекта и активировать окружение:

```bash
cd /Users/lev/PIS/hair_salon_style
source .venv/bin/activate
```

## 3. Запустить базы данных и Redis

```bash
docker compose up -d postgres postgres_test redis
```

В проекте поднимаются три контейнера:

- `postgres` — основная база данных;
- `postgres_test` — отдельная база для интеграционных тестов;
- `redis` — хранилище, которое использует приложение.

Проверить состояние контейнеров:

```bash
docker compose ps
```

Если сервис ещё запускается, дождитесь состояния `healthy` у PostgreSQL и Redis. Посмотреть сообщения контейнеров можно так:

```bash
docker compose logs --tail=100 postgres postgres_test redis
```

## 4. Создать таблицы основной базы

Миграции Alembic создают и обновляют структуру базы данных:

```bash
alembic upgrade head
```

Команду выполняйте из `hair_salon_style` при активированном виртуальном окружении. Она применяет миграции к основной базе из настроек `POSTGRES_*`.

## 5. Запустить сервер

```bash
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Оставьте это окно терминала открытым, пока работает сервер. Остановить его можно сочетанием `Ctrl+C`.

Проверить API можно в браузере:

- интерактивная документация: <http://127.0.0.1:8000/docs>;
- альтернативная документация: <http://127.0.0.1:8000/redoc>;
- OpenAPI-схема: <http://127.0.0.1:8000/openapi.json>.

Сервер запускается отдельно от Docker Compose. В Compose находятся базы и Redis, а FastAPI работает в активированном Python-окружении.

## 6. Запустить тесты

Сначала убедитесь, что запущены оба PostgreSQL-контейнера и Redis. Затем откройте отдельное окно терминала, перейдите в каталог проекта и активируйте `.venv`.

Все тесты:

```bash
pytest
```

Только модульные тесты:

```bash
pytest tests/unit
```

Только интеграционные тесты API:

```bash
pytest tests/integration
```

Интеграционные тесты отправляют запросы к приложению в памяти, без отдельного запущенного Uvicorn. Для них нужны тестовая PostgreSQL и Redis. Перед каждым интеграционным тестом фикстура применяет миграции к тестовой базе, а после теста откатывает их до пустой схемы. Укажите в `POSTGRES_DB_TEST` отдельную тестовую базу: её структура очищается после каждого теста.

Чтобы увидеть подробный список тестов и результат каждого:

```bash
pytest -v
```

Запустить один файл:

```bash
pytest tests/unit/test_services/test_service/test_get_services_service.py -v
```

## 7. Остановить вспомогательные сервисы

Когда работа закончена:

```bash
docker compose stop postgres postgres_test redis
```

Команда останавливает контейнеры, не удаляя их данные. Не используйте `docker compose down -v`, если хотите сохранить данные баз.

## Если что-то не запускается

- **Compose сообщает, что переменная не задана.** Проверьте наличие `.env` в `hair_salon_style` и заполните перечисленные выше переменные.
- **Ошибка подключения к PostgreSQL.** Сверьте адреса и порты в `.env` с опубликованными портами контейнеров; проверьте `docker compose ps`.
- **Ошибка подключения к тестовой БД.** Убедитесь, что контейнер `postgres_test` запущен и настройки `POSTGRES_*_TEST` совпадают с Compose.
- **Ошибка подключения к Redis.** Проверьте `REDIS_HOST`, `REDIS_PORT` и состояние контейнера `redis`.
- **Команда `pytest` не найдена.** Активируйте `.venv` и установите зависимости из `requirements.txt`.
- **Порт занят.** Освободите порт или измените опубликованный порт в `.env`, затем перезапустите соответствующий контейнер.
